# TRR-0020: no effective no-shortlist replacement established

The latest full canonical comparison also rejects warm-start quadratic refinement as a replacement. It is close in token accuracy on Pile, but loses159 additional Finance tokens and is slower on both benchmarks. All68 active method/setup cells are now complete. No tested rule yet meets the intended combination of baseline-like reconstruction and useful speed. The original goal remains active; these failures do not prove impossibility.

All new methods consider the complete 128,256-token vocabulary. They use no per-token shortlist and no separate A2 candidate reranker. They optimize only the current input; prefix weights stay frozen. Their initialization uses a table derived from the supplied public prefix, so they should not be described as lookup-free.

## What the algorithms do

Gini128 starts with a soft distribution over every token. One full sequence of probability-weighted embeddings passes through the frozen prefix. Gradients adjust the input probabilities to match the observed activations. A mild penalty after step32 encourages a discrete choice. The registered rule performs 128 updates and emits the final argmax.

Half-hard256 uses the same full-vocabulary input optimization, gradually blending half of each soft embedding with its current discrete argmax between steps64 and96. Gradients still pass through the full soft distribution. It performs 256 updates and selects the lowest whole objective after step96. That selection uses only observed activation error and the fixed rule.

Removing A1 saves a cheap proposal calculation, while these methods introduce many forward/backward optimization steps. Eliminating the candidate list therefore does not by itself guarantee a speed improvement.
