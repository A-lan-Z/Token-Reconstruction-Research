## 1. Establish the fitting-support hypothesis

Use existing public development resources to characterize the selected
positionwise model's errors by token frequency, prefix length/position,
and input style jointly where feasible.

TRR-0005's controlled substitutions were placed at positions >=128,
whereas the evaluated clips scored positions 1–127. Check what support
the fitting bank actually provides for rare token identities in the
evaluated prefix-length range.

This is a hypothesis to investigate, not an instruction to declare that
position mismatch caused the errors. Do not infer joint causes from
separate marginal summaries.

Keep prior evaluation findings descriptive. Choose new fitting examples
from permitted public resources and a documented sampling rule, not by
mining another study's hidden answers.

## 2. A bounded data-by-capacity comparison

Compare the current positionwise family with one genuinely more
expressive positionwise inverse, under:

- the current enriched fitting recipe;
- an improved public bank that broadens token/context support, including
  varied prefix lengths in the evaluation range.

A small crossed design is preferred. You may simplify it if an earlier
diagnostic makes a cell uninformative, but record why.

Keep a competent affine path in the stronger model. A small residual
nonlinear decoder is a reasonable option; choose a design that adds real
capacity rather than replacing the affine map with a restrictive
bottleneck.

Both models must use only the current activation at inference. No earlier
activation vectors, token-history input, teacher scores, candidate lists,
public-prefix calls, or A2 fallback.

Use ordinary full-vocabulary token supervision for this comparison.
Do not introduce a simultaneous teacher-objective experiment.

When comparing fitting distributions, prefer matched counts and
optimization opportunities. A modest unique-data scaling check is allowed
if it answers a specific remaining question. Track distinct examples,
token/context coverage, repeated exposures, and fitting compute separately.
Do not confound more unique data with an unexplained increase in training.

Generate controlled examples through real public-model forwards. Preserve
natural-text fitting and evaluation alongside any controlled supplement.

## 3. Make the training result interpretable

Check whether each model can improve on public examples it initially gets
wrong. A subset already classified perfectly at initialization is not a
capacity test.

Inspect training and held-out development curves. Distinguish
under-optimization, fitting capacity, and generalization.

Give the stronger model a reasonable opportunity to optimize rather than
treating one arbitrary short schedule as decisive. Keep this bounded:
one substantive architecture extension, not a broad optimizer or model
sweep.

Define a practically useful improvement before fresh evaluation, using
complete-clip recovery, token errors, and deployed cost. Matching the
existing standalone baseline is not the final research goal.

## 4. Evaluate quality on common natural inputs
