BLOCKING DEFECT 1 — THE BLIND SOURCE MAPPING WAS PUBLICLY RECOVERABLE BEFORE RECONSTRUCTION

The committed preregistration discloses, for every blind record:

the exact public dataset and immutable revision;

the exact zero-based dataset row index;

a record_id containing the dataset row index and a source-text hash prefix;

the complete SHA-256 of the source text;

the public deterministic selection seed and selection algorithm.


The record-selection implementation serializes each SelectedRecord with its index, record_id, text_sha256, and selection_key. The record ID itself is constructed as:

pile10k-<dataset-index>-<source-text-hash-prefix>.

The resource audit confirms that the exact pinned dataset was available and loadable offline in the execution environment.

Consequently, before the frozen reconstruction was produced, the source plaintext for every evaluated record could be recovered by reading the publicly committed row index from plan.json and loading that row from the pinned public dataset. Tokenization under the pinned tokenizer then yields the true evaluated token IDs.

This is not merely generic access to public auxiliary data. It is a direct mapping from the current observed record to its exact source plaintext.

The charter permits record identity and stage-local metadata only when that metadata does not encode source truth. It separately makes the current record’s source plaintext and true token IDs unavailable before reconstruction is frozen. The committed mapping violates that distinction.

The truth_opened: false flag and truth-sidecar gate protect only the separate truth file. They do not protect against this independently sufficient source-identity bridge.

BLOCKING DEFECT 2 — THE SAME TRUTH-RESOLVABLE MAPPING WAS PASSED TO THE RECONSTRUCTOR

The evaluator writes a nominally public observation index whose record entries contain:

record_id;

dataset_index;

text_sha256.


The reconstructor explicitly requires every record entry to contain exactly those three fields.

The reconstructor is also invoked with the complete committed plan containing all blind dataset indices, text hashes, selection seed, and deterministic selection rule.

The exact evaluated reconstruction command therefore supplied two truth-resolvable bridges:

1. experiments/TRR-0001/plan.json; and


2. outputs/TRR-0001/reconstructor_public/observation_index.json.



These are not opaque record identities. Given the pinned dataset, they identify the current source records exactly.

The resulting frozen outputs cannot be accepted as evidence that the reconstructor received only charter-permitted information.

BLOCKING DEFECT 3 — THE EVALUATOR/RECONSTRUCTOR SEPARATION IS NOT FAIL-CLOSED

The separation layer validates CLI path names and rejects several private-looking path fragments. It does not constrain which other files the reconstruction process can open.

The reconstruction process was run directly from the same repository workspace and user context in which the evaluator-private target LoRA, blind truth sidecar, source mapping, and dataset cache existed. No committed evidence establishes a container, mount namespace, dedicated user, file-permission boundary, or other process-level mechanism that made evaluator-private files unavailable.

The current separation test verifies the names of fields in the ReconstructionInputs dataclass and checks selected path fragments. It does not test the contents of the supplied plan or observation index, reject source-resolvable identifiers, or demonstrate that evaluator-private files are inaccessible to reconstruction code.

For a task whose explicit purpose includes fail-closed evaluator/reconstructor separation, API convention alone is insufficient. A reconstruction implementation with different code but the same nominal interface could read the current truth file or reconstruct it from the disclosed dataset row index.
