## Evidence to carry forward

TRR-0004's controlled no-bias affine fit improved public validation from 74.3377% with 5,000 fitting positions to 94.3505% with 124,371 positions under the same 3,000-update budget. This supports a fitting-data amount/diversity/generalization explanation; it does not isolate vocabulary coverage as the sole cause. Bias was a smaller effect.

The selected large affine's public-validation errors were 177/3,133. Of those, 120 occurred on token IDs absent from its fitting labels; 155 occurred on IDs seen at most four times. These are associations, not causal proof. Validation is not the fresh evaluation panel.

On fresh Pile records, the affine/attention scores were 84.94%/86.54% for the matched target and 84.29%/86.06% for the synthetic shift. Finance scores were 94.83%/95.18% and 94.83%/95.08%. A1+A2 remained near 99.8–99.95%. The attention exact-record gain was the same one Pile source record under both targets, not two independent successes. Historical A1 remains an important standalone comparator.

## 1. A bounded coverage-by-context comparison

Design a small crossed comparison between an original-like public fitting distribution and a coverage-enriched distribution, with a competent positionwise decoder and a compact activation-context decoder under both. Prefer matched fitting-position counts and comparable optimization opportunities, so distribution/coverage is not automatically confounded with simply seeing more examples. If you also increase data quantity, label and measure that separately.

The enriched distribution should improve diversity of token identities and their contexts, rather than merely repeat common Alpaca tokens. Mixed public natural text and a modest controlled token-in-public-context supplement are reasonable options; choose based on the existing error evidence. Do not select specific tokens or examples from hidden evaluation answers. Generate any synthetic activation pairs with actual public-model forwards; do not splice incompatible hidden-state rows. Retain natural-text evaluation even if fitting uses counterfactual token combinations.

Document unique token coverage, frequency distribution, context/domain mix, sequence geometry, unique examples, and training exposures. Reusing frozen public assets is encouraged. Avoid an exhaustive curriculum search.

## 2. Give the contextual extension an informative, fair test

The previous contextual branch froze a competent affine base and learned on the same public fitting corpus. Its selected checkpoint was step 25; sampled training batches were already almost perfect. Correct predictions still provide cross-entropy gradients, so this is not an invalid procedure, but it may be a weak setting for learning corrections to out-of-sample errors.

Check the base's error/loss on the examples used to train its extension. If it is essentially memorized, use an appropriate alternative: for example, a disjoint public correction-training portion supplied equally to positionwise and contextual arms, or a controlled joint-training design. Do not give only the contextual method extra data and attribute the resulting gain to context. Any training/selection/evaluation splits must remain distinct in role.

Also distinguish access to earlier activation vectors from other added-path differences. The existing attention path includes the current activation as well as prior ones; the MLP comparison alone does not isolate those inputs. Include one suitable trained context-off control or another convincing intervention. A post-hoc mask/shuffle is a useful sensitivity diagnostic, but distribution shift from that intervention is not by itself a fair trained-model comparison.

Keep same-position supervision: predict token x_i from H through position i, without source-token inputs, guessed-token feedback, future observations, candidate simulation, or A2 fallback. H_i already contains contextual information; the intervention tests the benefit of *additional earlier activation vectors*, not whether all context is dispensable.

## 3. Evaluate the practical question, not a pooled headline

Use a modest, separately selected public holdout with varied token identities and contexts. Keep already opened records as development/reproduction evidence, not fresh confirmation. Freeze choices before new evaluation and follow the charter's prediction/truth separation.

Compare all contenders on the same records. Report per-domain and per-target results; do not pool long Finance rows with short Pile rows or count paired target conditions as independent source records. Retain token accuracy, exact source-record recovery, gains and regressions, and record-level paired uncertainty. Diagnose errors jointly by token frequency and position/domain when feasible rather than inferring intersections from separate marginal tables.

Retain historical standalone A1 and a bounded A1+A2 quality anchor. No canonical all-method sweep is required for screening; no comparison-complete or replacement claim is authorized without the existing protocol. Use enough independent records to make the intended decision meaningful rather than another tiny endpoint-only panel.

Measure preparation/training, deployed footprint, and matched warmed inference. The method still needs to close a large quality gap: restoring historical A1 accuracy is a baseline milestone, not the final goal. Near-identical runtime numbers should not be interpreted as architectural speed gains.

## Decision and deliverables

Return the coverage-by-context comparison and a clear recommendation:

- If enriched fitting improves standalone quality and a practically important extra-context benefit can be excluded, prioritize the simpler positionwise path.
- If context retains a useful gain under equally good fitting, keep it and identify the remaining error type before enlarging the model.
- If uncertainty is too large, report an inconclusive pilot rather than equating a nonsignificant difference with no benefit.
- If neither change materially narrows the A1+A2 gap, identify what the remaining errors say about the objective or inverse mechanism; do not respond with an unbounded request for more of the same training.

Decide what constitutes a useful improvement before final evaluation, considering exact-record quality and added cost as well as token accuracy.
