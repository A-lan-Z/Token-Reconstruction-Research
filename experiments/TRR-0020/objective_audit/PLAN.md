# Canonical objective diagnostic, prospective before diagnostic evaluation

This is an analysis of already frozen reconstructions, not a new method and not a new performance comparison. Use192canonical inputs from both declared setups and four frozen outputs per input: latest native A1+A2, Gini128, halfhard256 and warm128white003. Their active68-cell reconstruction matrix remains unchanged. Verify every original output hash and never alter a token.

Run every complete hard reconstructed sequence through the same supplied prefix using native batch1 forward_full, BF16 weights, native unpadded geometry and FP32 cosine/MSE calculations. Save post-BOS cosine errors and MSE arrays for768cells. No optimization, proposals, reranking, corrections, target-prefix queries or parameter updates. Whole-sequence forward arithmetic is explicitly the diagnostic geometry; do not assume it is byte-equivalent to candidate-batch A2 or diagonal-gradient attention.

Repeat fixed public fixture seed200045 at128then40tokens three times exactly. Save before gates. Worst-case forward shape1x128x2048, no backward graph or vocabulary scoring table. Prior native controls peaked2.934GiB with additional A1 assets, so estimate<=3.3GiB and impose4GiB process cap with>=2GiB GPU free. The largest public qualifier must pass first. Live resource preflight is recorded separately. Expected<180seconds; fail-closed guard timeout600seconds. Do not overlap dev18 or any other GPU job.

Freeze all768diagnostic outputs and validate every source/input/output binding before opening labels. Gate must reject a missing cell, changed diagnostic output and changed prefix hash. The scorer reports each setup separately. Compare mean observed cosine error against token correctness. In addition, examine the first position where each novel output differs from baseline: earlier token IDs are then identical, so causal context is common. After labels open, count cases where that common prefix and baseline token are correct but the novel token is wrong. Classify novel loss as lower, within1e-6, or higher than baseline at that position.

Higher loss on those first mistakes indicates remaining optimization or approximation error under this diagnostic computation. Lower loss indicates that the supplied-prefix objective itself favors that wrong token in the shared context. Mixed results require separating causes. This cannot establish global optimality, impossibility, a universal lower bound or a deployable confidence threshold. Baseline tokens are comparator data only and must not become an input to a proposed reconstruction algorithm.
