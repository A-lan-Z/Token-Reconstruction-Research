# Agent 4 — Conditional native qualification of joint-activation proposals

## Read this result before launching anything

The attached prototype creates new token proposals using later observed activations.
It improved a narrow sequential control on synthetic models, but a wider ordinary
sequential control was more accurate and cheaper. It is NOT a rescued method.

This brief defines a bounded optional component gate, not another general rescue
campaign. Do not run a full natural benchmark, retrain a model, or build a recovered-
prefix framework on the basis of the toy result.

## Question

On the actual public prefix, do later observed activations generate a missing root
token more efficiently than an equally budgeted widening of current-token search?

The distinction from the rejected block selector is explicit: generate NEW proposals
from the whole block gradient. Do not just reassemble the old root shortlist.

## Starting point

Use your corrected, locally preserved implementation and its verified model package.
Read the report and prototype. Reuse the two diagnosed root positions as opened
mechanism diagnostics, plus at most 14 additional deterministic public diagnostic

Keep Agent 3's hybrid and other frozen studies unchanged. No merges, public disclosure

## The sole intervention

Use a three-position provisional window (shorter at record end), with real vocabulary
tokens at every position and at most two block hypotheses. Initialize without A1/B1
or a language model; use the existing permitted initializer or raw embedding lookup,
and include its cost.

Compute the sum of normalized observed-activation residuals through the fixed prefix.
One reverse pass gives gradients for all provisional embeddings. Generate new token
substitutions from vocabulary-wide proximal-gradient scores. Verify at most two
proposals per block position, retaining incumbents. Use no more than four rounds.

Compare with the identical block verification whose proposals only use the respective
position's own observation, AND with a wider ordinary sequential proposal budget.
The latter is the practical cost control, not the expensive diagnostic decomposition.

Future token guesses remain provisional real tokens. Never supply true future IDs,
insert the true root into a list, or allow arbitrary continuous future embeddings to
absorb the mismatch. Do not revise any committed token or current-record prefix weight.

## Measure before expanding

Start with one common context to measure native forward/backward and vocabulary costs.
Set a shared total work/wall budget from those measurements, not from the number of
candidate lists. The window design must not buy better recall through a larger budget.

Generate and freeze candidate lists before scoring against the opened labels.
Report newly included correct roots, lost correct proposals, and actual useful proposals
per measured budget. Record whether the root was verified or merely proposed.

Keep cache, RoPE, positional, precision and true input-embedding semantics intact.
A matched FP64 toy threshold is not a valid numerical acceptance threshold for Llama
or a mismatched recovered prefix. Use existing verified execution conventions.

## Decision

If wider local search matches or exceeds the new proposals at no greater cost, stop.
If joint evidence supplies no new useful candidate, stop.
If it supplies useful candidates but costs more than the shared budget, stop.

Only a favourable actual native proposal-and-cost result supports a separately planned
full reconstruction experiment. Return the component result first; do not automatically
launch that experiment or claim target tracking, overall speedup, or equivalent quality.

Preserve a small create-only report, lists and counters, with exact code/model identities.
Reuse the existing backup procedure. Do not rebuild evaluation infrastructure.
